Git é um sistema de código aberto para controle de versionamento de software distribuidos de arquivos, geralmente códigos-fonte de outros software. O git consegue fazer alterações de arquivos de maneiras que mantém histórico de versões, resolução de conflitos, possibilidades de rollback, merges, forks e etc...

GitHub é um serviso GIT na nuvem, onde você consegur criar repositórios de código-fonte e compartilhá-los com outras pessoas facilmente.

O Github é uma “rede social dev” em que é possível armazenar e compartilhar projetos de desenvolvimento de software.

O Git é um sistema de controle de versão de arquivos; em outras palavras, é responsável por guardar o histórico de alterações sempre que alguém modificar algum arquivo que está sendo monitorado por ele.

Um repositório é o elemento mais básico de GitHub. É um lugar onde você pode armazenar seu código, seus arquivos e o histórico de revisão de cada arquivo. Os repositórios podem ter vários colaboradores e podem ser públicos ou privados.

Um commit é como um checkpoint do seu projeto e um momento específico, funciona como uma foto de seu projeto, algo como um Ctrl+S em um documento, eles devem ser frequentemente refeitos para manter o projeto salvo

O git clone é um comando do Git usado para criar uma cópia local (clone) de um repositório existente que está hospedado em um servidor remoto(GitHub, Gitlab ou Bitbucket) ou em outra pasta em seu computador

Usar um sistema de controle de versões, as chamadas "logs", deixa o código mais organizado e bem estruturado registrando cada alteração ao longo do tempo, mantendo um histórico de alterações ao longo do tempo.

git add:  move as modificações do seu código para a área de preparação (staging area). Ele avisa que você quer incluir essas mudanças no próximo salvamento (commit).
git ignore:.gitignore é uma lista de regras que diz ao Git quais arquivos devem ficar invisíveis para o sistema de controle de versão. Ele serve para evitar o envio de senhas, dados temporários ou pastas pesadas de bibliotecas.
